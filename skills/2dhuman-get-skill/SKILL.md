# 2DHUMAN GET-skill

显示名称：2DHUMAN GET-skill。兼容调用标识：`2dhuman-get-skill`。

## 目标与路径

`{baseDir}` 指本 SKILL.md 所在目录，所有随附路径必须相对此目录解析为绝对路径，不能相对于用户工作目录猜测。

用户输出目录优先，否则当前工作目录。不要把新图写进 Skill 的 assets 目录。
固定风格参考：`assets/hunter-style-anchor.png`。
本流程默认使用宿主提供的 `generate_image` 文生图工具；用户明确选择其他模型/工具时尊重其选择，并说明未测试的迁移差异。工具不可用时可交付提示词，但不得声称已出图，也不得擅自改走收费服务。若当前宿主不支持参考图参数，不得伪造参数或声称锚点已被模型读取；须在提示词中用文字描述锚点风格，并在记录中注明本次为无参考图生成。

## 每次执行

### 1. 读取，而不是凭记忆复述

必须读取：
- `references/style-guide.md`
- `references/prompt-template.md`
- `assets/hunter-style-anchor.png`（实际查看图像）

需要本游戏设定时再读 `references/project-context.md` 和用户指定的新文档。用户当前设定优先于随附摘要；不要把本项目背景强加到其他项目。

### 2. 整理角色简报

提取：角色名/输出标识、世界背景、职业、经历、阵营、年龄与体型、服装、装备阶段、武器、动作、不可出现元素。
将信息分成“用户/原文事实”与“本次设计补充”。世界观和经历要转译为可见设计：布料、剪裁、磨损、随身物、持械方式、姿态，而不是把大段剧情原封不动塞进提示词。

用户授权自行设计时，缺少年龄/发型等可合理补齐并记录；关键设定冲突不能偷偷合并。不要每次重复询问已冻结的风格。

默认单张单角色、右向侧视、全身待机、简洁灰底。群像、场景、三视图和动画帧不在默认任务里。需要多角色时逐张生成，保持同一风格锚点。

### 3. 组装并保存实际提示词

按 `references/prompt-template.md` 组装完整英文提示词；替换所有占位符，保留风格与构图约束。先在输出目录保存 `<id>-prompt.md`，包括中文设计依据和完整实际英文提示词。

新角色：猎手参考只负责画法、比例、照明与构图，明确禁止继承猎手脸、绿色衣服、弓和箭袋。牧师不能因为参考图有弓而持弓。
同一角色延续：若宿主支持参考图，固定风格图作为 reference_images[0]，用户确认的人物图作为 reference_images[1]；在提示词里明确第一张负责风格，第二张负责身份、服装和配件。若同一张图承担两种用途，只传一次并说明。若宿主不支持参考图参数，明确告知用户本次只能按文字近似，不能保证身份或风格连续。

### 4. 调用一次生成工具

仅当当前宿主的图像工具 schema 明确支持 `reference_images` 时，才可按以下格式调用（这是参数示意，不是 shell 命令）：

```json
{
  "output_name": "<safe-id>-side-pixel-v001.png",
  "prompt": "<完整提示词>",
  "reference_images": ["<baseDir绝对路径>/assets/hunter-style-anchor.png"]
}
```

- 若当前工具不支持参考图参数，移除该参数；不要把本示例原样传给不兼容工具。
- output_name 使用英文字母、数字、连字符等工具支持的安全文件名。
- 先检查目标文件是否存在；已有则递增版本号，禁止覆盖用户确认的图。
- 初始猎手图使用工具默认尺寸；后续默认不传 size，以提示词约束横向构图。仅在当前工具支持且用户明确需要时指定尺寸，不能捏造枚举。
- 工具保存至工作目录。用户指定其他目录时，成功后将本次新生成文件移到目标目录并记录真实路径。
- 一次请求只生成一张。失败停止并报告；不自动重试，不静默切换模型或工具。
- 禁止读取或使用名为“废片”的目录中的文件。

### 5. 看图验收

成功后用图像读取工具查看实际文件，与固定猎手参考比较：
1. 单角色，全身和武器未裁切；无文字、水印、UI。
2. 朝右侧视，允许轻微转胸；不是等距俯视或正面立绘。
3. 写实偏风格化比例，非大头Q版；人物约占画面高度80–85%。
4. 清晰阶梯边缘、像素簇阴影与材质；不是平滑厚涂、照片、3D或简单马赛克滤镜。
5. 低饱和大地色体系，灰色简洁背景，上左光，短接地阴影。
6. 角色的职业、服装和武器正确；手、弓弦、持握与配件基本合理。
7. 新角色未被错误复制为猎手；已有角色身份未明显漂移。

记录 pass / partial / fail 与具体观察，不把“要求了24色”写成“已测得24色”。看不到实际图时记录 unverified，不能宣称已检查。部分不符如实交付并提示；未经用户进一步授权不自动重画。

### 6. 生成记录与交付

输出 `<id>-generation.json`，包含：skillVersion、角色简报（facts/designAdditions）、实际提示词路径、参考图绝对路径或空列表、输出实际路径、调用工具、实际使用参数、生成状态、逐项检查与差异说明。若工具不支持参考图，应明确记录未应用锚点图及原因。只记录实际知道的模型/尺寸/seed，不编造隐藏参数。不保存密钥、临时签名链接或内部标识。

最终简短给出图片、提示词、记录路径，说明有无明显偏差。不要宣称“完全一致”“固定seed锁脸”或“可直接导入游戏”。

## 一致性与迭代边界

- 支持参考图的宿主中，后续每张都直接引用固定猎手图，不用不断把上一张生成结果作为唯一参考，避免风格逐代偏移。无参考图能力的宿主只能通过提示词近似风格，不承诺身份锁定或稳定连续性。
- 不以文字约束冒充严格像素网格、限定色板或透明通道验证。
- 这是像素角色原画，不是已经完成尺寸规范、抠图、动作拆帧的游戏资源。
- 用户确认改变风格时才创建新风格版本；保留旧锚点和旧模板，不静默覆盖。
